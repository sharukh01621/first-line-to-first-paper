Learning Objectives

By the end of this chapter, you will be able to:

  1. Express clinical reference intervals cleanly using Python’s six comparison operators and chained comparisons (e.g., 90 <= sbp_mmhg < 120).
  2. Combine multi-factor screening rules accurately using Boolean truth tables (and, or, not), operator precedence, and explicit parentheses.
  3. Translate clinical guidelines—such as WHO BMI classification, WHO maternal anemia severity, and Upazila clinic triage—into mutually exclusive if / elif / else decision trees without falling into the silent if-vs.-elif overwrite bug.

4.1 Stage 1 — First-Principles Intuition: Clinical Triage Protocols as Boolean Gates

Up to Chapter 3, every Python script you wrote ran strictly top-to-bottom—like a single-lane corridor where every single line executes unconditionally. Real medicine and public health never work that way.

When a mother walks into an Upazila Health Complex in Sylhet or Rangpur, a triage nurse does not give every patient the exact same treatment. Instead, the nurse walks down a rapid yes/no decision checklist:

  • Is hemoglobin missing (None or 999)? \(\rightarrow\) Flag for lab draw immediately.
  • Is hemoglobin below \(7.0\text{ g/dL}\)? \(\rightarrow\) Severe anemia (urgent referral!).
  • Otherwise, is it below \(10.0\text{ g/dL}\)? \(\rightarrow\) Moderate anemia.
  • Otherwise, is it below \(11.0\text{ g/dL}\)? \(\rightarrow\) Mild anemia.
  • Otherwise? \(\rightarrow\) Normal.
NoteMental Model — Every Branch Asks a Yes/No (Boolean) Question

In Python, a conditional statement (if, elif, else) is a railroad switch controlled by a Boolean expression (True or False).

  • Boolean expressions are the questions (hb_g_dl < 7.0, sbp_mmhg >= 140 and has_headache).
  • Indented code blocks (4 spaces after a colon :) are the actions taken only when that specific track is switched open.
  • In an if / elif / else chain, Python walks top-to-bottom and executes at most one branch—the very first condition that evaluates to True—then jumps straight to the end of the entire chain.

4.1.1 Boolean Truth Tables (and, or, not)

Every compound clinical rule boils down to three logical operators named after 19th-century mathematician George Boole:

A B A and B (Both true) A or B (At least one true) not A (Flip)
True True True True False
True False False True False
False True False True True
False False False False True

4.1.2 Operator Precedence & Python’s Indentation Law

When mixing logical operators in one expression, Python always evaluates in strict priority order:

\[\text{Comparisons } (<, \le, ==, \neq, \ge, >) \;\longrightarrow\; \texttt{not} \;\longrightarrow\; \texttt{and} \;\longrightarrow\; \texttt{or}\]

Just like arithmetic PEMDAS, never force a reader to memorize precedence during clinical triage—wrap compound clauses in explicit parentheses so your scientific intent is unmistakable!

4.3.1 Comparison Operators & Chained Clinical Ranges

Python supports all six relational operators (==, !=, <, <=, >, >=)—and unlike C or Java, Python lets you chain comparisons directly just as you write them in biostatistics papers:

sbp_mmhg = 114
hb_g_dl = 12.2
temp_c = 38.4

# Chained comparisons mirror clinical reference intervals directly
is_normal_bp = 90 <= sbp_mmhg < 120
is_normal_hb = 11.0 <= hb_g_dl <= 16.0
has_fever = temp_c >= 38.0

print("Normal BP:", is_normal_bp)
print("Normal Hb:", is_normal_hb)
print("Has Fever:", has_fever)

Expected Output:

Normal BP: True
Normal Hb: True
Has Fever: True

Under the hood, Python translates 90 <= sbp_mmhg < 120 into (90 <= sbp_mmhg) and (sbp_mmhg < 120)—evaluating sbp_mmhg only once and keeping the clinical interval crystal clear.

4.3.2 Boolean Algebra (and, or, not) & Operator Precedence

In outbreak surveillance, case definitions almost always combine multiple symptoms and vaccination status:

has_fever = True
has_rash = True
is_vaccinated = False

# Precedence: not > and > or (parentheses make clinical intent explicit!)
suspect_measles = has_fever and has_rash and (not is_vaccinated)
needs_isolation = suspect_measles or (has_fever and not is_vaccinated)

print("Suspect measles:", suspect_measles)
print("Needs isolation:", needs_isolation)

Expected Output:

Suspect measles: True
Needs isolation: True
TipResearcher’s Note — Always Write == for Equality, Never =

Remember Chapter 2: a single = assigns a value (age = 30), whereas a double == tests equality (age == 30 \(\rightarrow\) True or False). For checking None, Python best practice uses the identity operator is None or is not None rather than == None.

4.3.3 if / elif / else Clinical Decision Trees & the if vs. elif Bug

Compare these two side-by-side WHO maternal anemia classifiers on a critically ill mother whose hemoglobin is hb_g_dl = 6.4 g/dL:

# Correct WHO maternal anemia severity ladder (mutually exclusive elif)
hb_g_dl = 6.4

if hb_g_dl < 7.0:
    severity = "Severe"
elif hb_g_dl < 10.0:
    severity = "Moderate"
elif hb_g_dl < 11.0:
    severity = "Mild"
else:
    severity = "Normal"

print(f"Hb {hb_g_dl} g/dL -> Correct severity: {severity}")

Expected Output:

Hb 6.4 g/dL -> Correct severity: Severe

Now watch what happens if a hasty programmer writes three separate if statements instead of elif:

# Silent Logic Bug: independent 'if' statements overwrite earlier matches!
hb_g_dl = 6.4
buggy_severity = "Normal"

if hb_g_dl < 7.0:
    buggy_severity = "Severe"
if hb_g_dl < 10.0:
    buggy_severity = "Moderate"
if hb_g_dl < 11.0:
    buggy_severity = "Mild"   # DANGEROUS: overwrites 'Severe' with 'Mild'!

print(f"Hb {hb_g_dl} g/dL -> Buggy severity:   {buggy_severity}")

Expected Output:

Hb 6.4 g/dL -> Buggy severity:   Mild
WarningSilent Clinical Danger — No Error Message, Wrong Diagnosis!

Notice that Python raised zero exceptions in the buggy cell! Because \(6.4 < 7.0\) is True, and \(6.4 < 10.0\) is True, and \(6.4 < 11.0\) is True, every independent if block executed in sequence—silently downgrading a life-threatening Severe anemia case to Mild. Whenever categories are mutually exclusive, always link them with elif.

4.3.4 Short-Circuit Evaluation & Defensive Guard Clauses

Python evaluates and and or lazily from left to right:

  • In A and B, if A is False, the entire expression can never be True—so Python stops immediately and never evaluates B.
  • In A or B, if A is True, the entire expression is already True—so Python stops immediately and never evaluates B.

This behavior—called short-circuit evaluation—lets you place a guard condition on the left to protect dangerous operations (like dividing by a possibly zero population or comparing a possibly None lab value) on the right:

# Guard 1: Short-circuit prevents ZeroDivisionError when population == 0
cases = 18
population = 0

high_outbreak = population > 0 and (cases / population) * 100000 >= 50.0
print("High outbreak (safely guarded):", high_outbreak)

# Guard 2: Missing-value guard intercepts BOTH None and DHS sentinel 999
raw_hb = 999
if raw_hb is None or raw_hb == 999:
    hb_label = "Missing"
elif raw_hb < 11.0:
    hb_label = "Anemic"
else:
    hb_label = "Normal"

print("Guarded Hb status:", hb_label)

Expected Output:

High outbreak (safely guarded): False
Guarded Hb status: Missing

Look closely at Guard 2: in real DHS, MICS, and hospital EHR exports, missing laboratory values are frequently coded as numeric sentinels like 999 or -9. If you forget to check raw_hb == 999 first, Python happily evaluates 999 < 11.0 as False and misclassifies a patient who never got a blood test as "Normal"!

4.3.5 Break It On Purpose! (Conditional & Guard Error Anatomy)

ImportantBreak It On Purpose #1 — TypeError Comparing None to a Number 
hb_g_dl = None
is_anemic = hb_g_dl < 11.0

Python’s Traceback:

TypeError: '<' not supported between instances of 'NoneType' and 'float'

Diagnosis: Unlike ==, Python refuses to order None relative to a float—protecting you from silently treating missing measurements as zero.
Fix: Guard None first: is_anemic = (hb_g_dl is not None) and (hb_g_dl < 11.0).

ImportantBreak It On Purpose #2 — ZeroDivisionError from Reversed Guard Order 
cases = 12
population = 0
high_rate = (cases / population) > 0.05 and population > 0

Python’s Traceback:

ZeroDivisionError: division by zero

Diagnosis: The author wrote the right guard (population > 0), but placed it on the right side of and! Because Python evaluates left-to-right, cases / population crashed before Python ever reached the guard.
Fix: Always put the guard first: high_rate = population > 0 and (cases / population) > 0.05.

ImportantBreak It On Purpose #3 — NameError on Lowercase Boolean 
is_eligible = true

Python’s Traceback:

NameError: name 'true' is not defined

Diagnosis: Unlike JavaScript, R (TRUE), or JSON (true), Python’s Boolean literals are strictly capitalized True and False. Writing lowercase true makes Python search for a variable named true.
Fix: Capitalize the first letter: is_eligible = True.

4.4 Stage 4 — The Researcher’s Problem-Structuring Blueprint

Scenario: Build an automated Upazila Health Complex Maternal Triage Router. Given a pregnant patient’s hemoglobin (hb_g_dl = 6.8), systolic blood pressure (sbp_mmhg = 152), and severe headache symptom (has_headache = True), classify her WHO maternal anemia severity (with a missing-value guard for None or 999), flag potential preeclampsia (sbp_mmhg >= 140 AND has_headache), and route her clinic triage_priority:

  • "Urgent" if anemia_grade == "Severe" OR sbp_mmhg >= 160 OR preeclampsia_flag
  • "Moderate" if anemia_grade == "Moderate" OR sbp_mmhg >= 140
  • "Routine" otherwise

4.4.1 Blueprint (Completed on Paper Before Coding)

  1. Inputs & Units: hb_g_dl (g/dL, possibly None or 999), sbp_mmhg (mmHg), has_headache (bool).
  2. Edge Cases & Traps:
    • Guard hb_g_dl is None or hb_g_dl == 999 at the very top of the anemia ladder before < 7.0.
    • Use mutually exclusive elif branches so "Severe" cannot be overwritten by "Mild".
    • Test "Urgent" before "Moderate" in the triage router so high-risk red flags always win.
  3. Step-by-Step Algorithm:
    1. Classify anemia_grade via guarded if / elif / else.
    2. Compute preeclampsia_flag = (sbp_mmhg >= 140) and has_headache.
    3. Route triage_priority from most urgent ("Urgent") to least urgent ("Routine").
    4. Print a clean structured triage summary.
  4. Verification Plan (Hand Check):
    • hb_g_dl = 6.8 < 7.0 \(\Rightarrow\) anemia_grade = "Severe".
    • sbp_mmhg = 152 >= 140 and has_headache = True \(\Rightarrow\) preeclampsia_flag = True.
    • Both red flags trigger the first branch \(\Rightarrow\) triage_priority = "Urgent".

4.4.2 Clean Python Implementation (Verbatim in 01_walkthrough.ipynb)

# Step 1: Patient intake readings from Upazila Health Complex
hb_g_dl = 6.8
sbp_mmhg = 152
has_headache = True

# Step 2: Missing-value guard + WHO maternal anemia classification
if hb_g_dl is None or hb_g_dl == 999:
    anemia_grade = "Missing"
elif hb_g_dl < 7.0:
    anemia_grade = "Severe"
elif hb_g_dl < 10.0:
    anemia_grade = "Moderate"
elif hb_g_dl < 11.0:
    anemia_grade = "Mild"
else:
    anemia_grade = "Normal"

# Step 3: Preeclampsia warning & clinic triage routing
preeclampsia_flag = (sbp_mmhg >= 140) and has_headache

if anemia_grade == "Severe" or sbp_mmhg >= 160 or preeclampsia_flag:
    triage_priority = "Urgent"
elif anemia_grade == "Moderate" or sbp_mmhg >= 140:
    triage_priority = "Moderate"
else:
    triage_priority = "Routine"

# Step 4: Structured clinical triage readout
print(f"Anemia: {anemia_grade} | Preeclampsia Flag: {preeclampsia_flag}")
print(f"Upazila Triage Priority: {triage_priority}")

Output:

Anemia: Severe | Preeclampsia Flag: True
Upazila Triage Priority: Urgent

4.8.1 A. Concept & Execution Trace Test Key

  1. False—because the right half 120 < 120 is strictly false (120 is equal to 120, not less than it).
  2. True—because and has higher precedence than or, so Python evaluates True or (False and False) \(\rightarrow\) True or False \(\rightarrow\) True.
  3. "Normal"—because the second if is independent (not elif), so 17.2 < 25.0 executes and overwrites "Underweight".
  4. With population > 0 on the left, it does not crash (False short-circuits immediately). Swapping them raises ZeroDivisionError.
  5. (not is_pregnant) and (not has_allergy).
  6. 999 < 11.0 evaluates to False, and if you also have an else: "Normal" or forgot to check 999 before numeric ranges (e.g., raw_hb >= 11.0), the missing code 999 gets misclassified as a valid reading instead of "Missing".
  7. lab_result is None (and lab_result is not None).
  8. "Moderate"! Because 175 >= 140 matches first, Python never reaches elif sbp >= 160—always put stricter thresholds first!
  9. NameError: name 'false' is not defined (Python requires capitalized False).
  10. "Moderate"—because 7.0 < 7.0 is False, so execution falls to elif hb < 10.0, which is True.

4.8.4 D. Debugging Post-Mortem: Top 3 Chapter 4 Failure Modes

  1. Missing Parentheses Around Mixed and / or Clauses (Task 4.1): Writing bmi_category == "Underweight" and anemia_severity == "Severe" or anemia_severity == "Moderate" evaluates as (Underweight and Severe) or Moderate because and binds tighter than or—misclassifying a normal-weight mother with moderate anemia as high-risk malnutrition! Always wrap or clauses in explicit parentheses.
  2. Unreachable Shadowed Branches (Question 8 & Task 4.2): Checking a broad rule (sbp >= 140 or temp_c >= 38.5) above a stricter critical rule (sbp >= 160 or platelets_k < 50) permanently shadows the emergency branch. Always order triage ladders from highest urgency / strictest threshold down to routine.
  3. Late Missing-Value & Zero-Denominator Guards (Task 4.3): Checking cases / pop before pop > 0 triggers ZeroDivisionError, and checking hb < 11.0 before hb is None or hb == 999 either crashes with TypeError or silently turns a missing survey code (999) into a "Normal" lab result. Notice also how repetitive writing Ward A and Ward B twice felt in Task 4.3—in Chapter 5 (Loops) and Chapter 6 (Functions), we will eliminate that repetition forever!
