Learning Objectives

By the end of this chapter, you will be able to:

  1. Extract structured fields from clinical IDs and barcodes using 0-based indexing, negative indexing, and half-open slicing (s[start:stop]).

3.1 Stage 1 — First-Principles Intuition: Laminated Hospital Wristbands

In public health and clinical research, over 70% of your real-world cleaning time happens on text: misspelled district names (" sylhet_sadar "), pipe-delimited hospital lab feeds ("PAT_109 | 38.4 C | pos"), structured specimen barcodes ("BD-CTG-2026-0094-MAL"), and blood pressure readings stuck together with a slash ("148/92 mmHg").

Before writing a single string method, anchor two permanent mental rules:

NoteMental Model — The Laminated Clinical Wristband

Picture a sealed, laminated patient wristband printed with a 16-character barcode (BD-DHK-2026-0042). Two physical laws govern every Python str object:

  1. Every Character Has Two Addresses: Counting from the left starts at 0 (not 1!), so the last character sits at len(s) - 1. Counting backwards from the right starts at -1 (-1 is the final character, -2 is second-to-last, and so on).
  2. The Band Is Permanently Laminated (Immutable): Once a str object is created in memory, you can never scratch out or overwrite a single character inside it. If you want to fix a typo or strip spaces, Python prints a brand-new laminated wristband in a new memory slot—and unless you attach a variable name tag (clean = ...) to that new band, it falls straight into the trash!

3.1.1 Why Half-Open Slicing ([start:stop]) Is Brilliant

When slicing s[start:stop], Python includes the character at start and stops right before stop (excluding stop). Mathematicians write this as the half-open interval \([ \text{start}, \text{stop} )\). That single design choice gives you two superpowers:

  • Instant Length Formula: The length of s[start:stop] is always stop - start (e.g., patient_id[3:6] has exact length \(6 - 3 = 3\) characters: "DHK").
  • Seamless Adjacent Splits: s[:k] + s[k:] always reconstructs the exact original string s with zero overlap and zero missing characters!

3.3.3 Splitting Delimited Records & Joining Fields

Hospital lab systems (such as HL7 feeds) frequently separate columns with pipe symbols (|) or semicolons (;) instead of commas. Calling .split("|") breaks one raw row into indexable pieces (parts[0], parts[1], …), and ",".join([...]) reassembles clean string tokens into a standard CSV line:

raw_row = "  PAT-019 | 31 | 10.4 g/dL | positive  "
parts = raw_row.split("|")

pat_id = parts[0].strip()
age = int(parts[1].strip())
hb = float(parts[2].replace("g/dL", "").strip())
status = parts[3].strip().upper()

# Reassemble a clean CSV row with .join()
clean_csv = ",".join([pat_id, str(age), str(hb), status])
print("Clean CSV row:", clean_csv)

Expected Output:

Clean CSV row: PAT-019,31,10.4,POSITIVE

Notice that ",".join(...) requires every item in the list to be a str—that is why we wrap str(age) and str(hb) before joining!

3.3.4 Publication-Grade f-String Formatting

When reporting epidemiological tables or manuscript statistics, raw floating-point prints like 0.02233062330623306 look amateurish. Python f-strings accept a mini-language after a colon : inside {...} to format numbers with journal-grade precision:

Format Specifier Meaning Input \(\rightarrow\) Output
:.1f / :.2f Fixed decimal places 128.467 \(\rightarrow\) 128.5
:, Thousands comma separator 18450 \(\rightarrow\) 18,450
:.2% Multiply by \(100\) & append % 0.02233 \(\rightarrow\) 2.23%
:04d Zero-padded integer (width 4) 42 \(\rightarrow\) 0042
:<14 / :>10 Left- or right-align in fixed width "Site" \(\rightarrow\) "Site " 
site = "Chattogram"
seq_num = 42
screened = 18450
cases = 412
positivity = cases / screened
mean_sbp = 128.467

print(f"Facility ID : CTG-{seq_num:04d}")
print(f"Screened    : {screened:,} adults")
print(f"Positivity  : {positivity:.2%} ({cases} / {screened:,})")
print(f"Mean SBP    : {mean_sbp:.1f} mmHg")
print(f"{'Site':<14} | {'Screened':>10} | {'Positivity':>10}")
print(f"{site:<14} | {screened:>10,} | {positivity:>10.2%}")

Expected Output:

Facility ID : CTG-0042
Screened    : 18,450 adults
Positivity  : 2.23% (412 / 18,450)
Mean SBP    : 128.5 mmHg
Site           |   Screened | Positivity
Chattogram     |     18,450 |      2.23%
WarningCommon Trap — Never Multiply by 100 When Using :.2%

Python’s % format specifier already multiplies by 100! If positivity = 0.02233, writing {positivity:.2%} gives 2.23%. Writing {positivity * 100:.2%} accidentally multiplies by \(100\) twice and prints 223.31%!

3.3.5 Interactive User Input (input()) & Validation Hygiene

In an interactive Python script or Colab cell, input("Prompt: ") pauses execution, waits for the user to type text and press Enter, and always returns a str—even when the user types 38.4 or 28.

Because interactive input() pauses execution forever in automated research pipelines and cloud notebook runners, disciplined researchers isolate raw input at the top of a cell (or simulate it cleanly during automated testing):

# In an interactive Colab session, you can uncomment the line below:
# raw_temp = input("Enter patient temperature (e.g., 38.4 C): ")

# For reproducible, non-blocking execution, we simulate the user's text:
raw_temp = "  38.4 C  "
print("Raw input type:", type(raw_temp), "| Value:", repr(raw_temp))

temp_c = float(raw_temp.replace("C", "").strip())
has_fever = temp_c >= 38.0
print(f"Parsed Temp: {temp_c:.1f} C | Fever Flag: {has_fever}")

Expected Output:

Raw input type: <class 'str'> | Value: '  38.4 C  '
Parsed Temp: 38.4 C | Fever Flag: True

Golden Rule of User Input: Treat every string returned by input() as untrusted messy text—always .strip() whitespace, strip expected units, and explicitly cast to int or float before arithmetic!

3.3.6 Break It On Purpose! (String Error Anatomy)

ImportantBreak It On Purpose #1 — IndexError (Off-by-One Indexing) 
code = "DHK-042"
last_char = code[7]

Python’s Traceback:

IndexError: string index out of range

Diagnosis: len("DHK-042") is 7, which means valid positive indices run from 0 through 6 (len(code) - 1). Index 7 steps one slot past the end of the string!
Fix: Use negative indexing code[-1] (always the last character, regardless of length) or code[len(code) - 1].

ImportantBreak It On Purpose #2 — TypeError (String Immutability) 
patient_id = "uhc-0042"
patient_id[0] = "U"

Python’s Traceback:

TypeError: 'str' object does not support item assignment

Diagnosis: Python strings are immutable—you cannot modify individual characters in place.
Fix: Construct a brand-new string via slicing/concatenation (patient_id = "U" + patient_id[1:]) or .upper() (patient_id = patient_id.upper()).

ImportantBreak It On Purpose #3 — ValueError on Dirty Unit String 
raw_temp = "38.6 C"
temp_c = float(raw_temp)

Python’s Traceback:

ValueError: could not convert string to float: '38.6 C'

Diagnosis: float() tolerates outer spaces (float(" 38.6 ") succeeds), but crashes on non-numeric unit suffixes like "C", "kg", or "mmHg".
Fix: Strip the unit first: temp_c = float(raw_temp.replace("C", "").strip()).

3.4 Stage 4 — The Researcher’s Problem-Structuring Blueprint

Scenario: A rural community health worker texts a rapid dengue triage SMS to the district surveillance desk: raw_sms = " barishal_sadar | 007 | 39.1 C | 112000 /uL ". The four pipe-delimited fields represent upazila name, patient serial number, body temperature (\(^\circ\text{C}\)), and platelet count (normal \(\ge 150{,}000\text{ /}\mu\text{L}\)). Parse all fields cleanly, generate a zero-padded case ID ("BRS-0007"), evaluate urgent_referral (True if febrile \(\ge 38.0^\circ\text{C}\) and platelets \(< 150{,}000\)), and print a clean two-line clinical alert.

3.4.1 Blueprint (Completed on Paper Before Coding)

  1. Inputs & Units: One raw str containing 4 |-separated fields: messy text (upazila), zero-padded integer (serial), float with "C" unit (temp_c), and integer with "/uL" unit (platelets).
  2. Edge Cases & Traps:
    • Leading/trailing spaces inside every token after .split("|").
    • Unit suffixes ("C", "/uL") will trigger ValueError if not removed before float()/int().
    • Calling int("007") turns "007" into 7; we must re-pad with :04d to format "BRS-0007".
  3. Step-by-Step Algorithm:
    1. Split raw_sms on "|" into parts.
    2. Clean parts[0] with .strip().replace("_", " ").title().
    3. Parse serial, temp_c, and platelets after removing units and whitespace.
    4. Build case_id = f"BRS-{serial:04d}", compute boolean flags, and print formatted alert lines.
  4. Verification Plan (Hand Check):
    • upazila \(\rightarrow\) "Barishal Sadar"; case_id \(\rightarrow\) "BRS-0007".
    • 39.1 >= 38.0 (True) and 112000 < 150000 (True) \(\Rightarrow\) urgent_referral = True.
    • 112000 with :, prints "112,000".

3.4.2 Clean Python Implementation (Verbatim in 01_walkthrough.ipynb)

# Step 1: Raw incoming clinic SMS text
raw_sms = "  barishal_sadar | 007 | 39.1 C | 112000 /uL  "

# Step 2: Split on '|' and sanitize each text field
parts = raw_sms.split("|")
upazila = parts[0].strip().replace("_", " ").title()
serial = int(parts[1].strip())
temp_c = float(parts[2].replace("C", "").strip())
platelets = int(parts[3].replace("/uL", "").strip())

# Step 3: Derive clinical triage flags & standardized ID
case_id = f"BRS-{serial:04d}"
is_febrile = temp_c >= 38.0
low_platelets = platelets < 150000
urgent_referral = is_febrile and low_platelets

# Step 4: Format publication-clean clinical alert
print(f"[{case_id}] {upazila} | Temp: {temp_c:.1f} C")
print(f"Platelets: {platelets:,} /uL | Urgent Referral: {urgent_referral}")

Output:

[BRS-0007] Barishal Sadar | Temp: 39.1 C
Platelets: 112,000 /uL | Urgent Referral: True

3.8 Stage 8 — Complete Annotated Solutions & Debugging Post-Mortem

3.8.1 A. Concept & Execution Trace Test Key

  1. len(code) is 7; code[7] raises IndexError because valid positive indices are 0 through 6.
  2. s[0:3] returns "EPI" (length \(3 - 0 = 3\)); s[-4:] returns "LOGY".
  3. Prints ' dhaka '! Because strings are immutable, city.strip().upper() created a new string and immediately discarded it since it was never reassigned (city = ...).
  4. Fails because str objects are immutable; Python raises TypeError ('str' object does not support item assignment).
  5. serial_str preserves leading zeros ("0042", str); int("0042") drops leading zeros and evaluates to integer 42 (int).
  6. Produces ["148", "92"]—a list of strings (str), not integers! Always cast with int(...) before comparing blood pressures numerically.
  7. f"{rate:.1%}" produces "4.5%". Writing f"{rate * 100:.1%}" multiplies by \(100\) twice and wrongly prints "450.0%"!
  8. Evaluates to "PAT-00019" (:05d pads 19 with three leading zeros to reach an exact total width of 5 digits).
  9. Always returns <class 'str'>—input() never automatically converts text to float or int.
  10. raw = " malaria_pos " \(\rightarrow\) clean = "MALARIA_POS" \(\rightarrow\) result = "MALARIA-POS".

3.8.4 D. Debugging Post-Mortem: Top 3 Chapter 3 Failure Modes

  1. The Silent Immutability Trap (raw.strip() Without Assignment): Calling raw_district.strip() looks like it should clean raw_district, and Python produces zero error message—yet raw_district stays completely unchanged! Always bind the returned copy (clean_district = raw_district.strip()).
  2. Double-Multiplying Percentages ({rate * 100:.2%}): Because the % format specifier automatically multiplies proportions by \(100\), multiplying by 100 beforehand turns a 1.76% Case Fatality Rate into an impossible 175.78%! Always pass the raw decimal proportion (deaths / confirmed_cases) directly into :.2%.
  3. Hidden Spaces Breaking .endswith() and Exact Matching: Checking raw_barcode.upper().endswith("MAL") before calling .strip() silently returns False because the last two characters are spaces (" "), not "MAL"! Make .strip() the very first link in every text-cleaning chain.
