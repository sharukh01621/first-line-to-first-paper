5  Loops, Iteration Patterns, Accumulators, and Execution Tracing

Chapter Mission: Automate repetitive epidemiological calculations across hundreds or millions of patient records using for and while loops, master the 4 Universal Loop Patterns (Accumulator, Counter, Filter, Running Max/Min), control iteration flow with range(), enumerate(), continue, and break, and trace every variable state on paper using Loop Execution Trace Tables.

Learning Objectives

By the end of this chapter, you will be able to:

  1. Iterate cleanly over sequences and integer ranges using for loops and the half-open interval range(start, stop, step).
  2. Implement the 4 Universal Loop Patterns—Accumulator, Counter, Filter, and Running Max/Min—in a single clean pass over clinical data.
  3. Skip DHS missing-value sentinels (999, None) with continue and exit outbreak scans early with break.
  4. Track human-readable 1-based weeks or days alongside values using enumerate(..., start=1).
  5. Model unknown-duration processes—such as epidemic doubling and hospital bed surge capacity—using condition-driven while loops without creating infinite loops.
  6. Build Loop Execution Trace Tables to verify nested loops, catch off-by-one bugs, and prevent TypeError, NameError, and ZeroDivisionError.

5.1 Stage 1 — First-Principles Intuition: The Triage Conveyor Belt

In Chapter 2, you totaled 4 days of dengue cases by writing four copy-pasted lines: total_cases += day_1, += day_2, += day_3, += day_4. That works for 4 days—and collapses completely when your thesis analyzes 365 days of national surveillance across 64 districts or 20,000 mothers in the Bangladesh DHS.

Loops let you write the clinical rule once and instruct Python to apply it faithfully to every patient record automatically.

NoteMental Model — The Hospital Triage Conveyor Belt

Picture two different stations in a district hospital:

  1. The for Loop (Fixed Stack of Patient Charts): A triage nurse receives a finite stack of charts (hb_readings). She picks up Chart 1, checks hemoglobin, updates her clipboard tallies (total_hb, anemic_count), sets it down, and repeats for Chart 2, Chart 3, …, stopping automatically when the stack is empty.
  2. The while Loop (Emergency Ward Bed Monitor): A hospital director watches active dengue admissions climb day by day. She does not know in advance whether beds will run out on Day 6 or Day 14—she simply keeps simulating “as long as occupied_beds <= bed_capacity,” stopping the moment capacity is breached.

5.1.1 Choosing for vs. while

Loop Type When to Choose It Public Health Example
for loop You have a known collection (list of readings) or exact count (range(1, 8)). Computing clean mean hemoglobin across 500 survey rows.
while loop You do not know how many steps it will take until a condition becomes False. Simulating days until epidemic doubling overflows 200 hospital beds.

5.2 Stage 2 — Visual Mental Model: The Loop Execution Cycle

Every loop in Python—whether processing 5 clinic rows or 50 million genomic reads—follows the exact same cyclic execution engine:

Golden Rule of Loop Initialization: Always initialize accumulators (total = 0), counters (count = 0), and filter lists (results = []) ONCE before the loop begins. Putting total = 0 inside the loop body wipes out your progress on every iteration; forgetting it entirely triggers a NameError!

5.3.1 for Loops & range() (Half-Open Intervals)

Python’s range(start, stop, step) follows the half-open mathematical interval \([start, stop)\)—it includes start and stops one step before stop.

# range(start, stop, step) stops BEFORE 'stop' (half-open interval)
for day in range(1, 6):
    print(f"Day {day}: Surveillance report submitted")

print("Days counted:", list(range(1, 6)))
print("Even clinic hours:", list(range(8, 17, 2)))

Expected Output:

Day 1: Surveillance report submitted
Day 2: Surveillance report submitted
Day 3: Surveillance report submitted
Day 4: Surveillance report submitted
Day 5: Surveillance report submitted
Days counted: [1, 2, 3, 4, 5]
Even clinic hours: [8, 10, 12, 14, 16]

5.3.2 The 4 Universal Loop Patterns

Over 90% of real-world data processing loops are combinations of just four universal patterns:

  1. Accumulator: Running sum (total_hb += hb), initialized to 0 or 0.0.
  2. Counter: Running tally of matching records (anemic_count += 1), initialized to 0.
  3. Filter: Growing list of qualifying items (anemic_cases.append(hb)), initialized to [].
  4. Running Max / Min: Tracking the extreme value seen so far (max_hb = hb_readings[0]).
hb_readings = [10.4, 12.1, 9.6, 11.8, 10.9]

total_hb = 0.0           # Pattern 1: Accumulator
anemic_count = 0         # Pattern 2: Counter
anemic_cases = []        # Pattern 3: Filter
max_hb = hb_readings[0]  # Pattern 4: Running Max

for hb in hb_readings:
    total_hb += hb
    if hb < 11.0:
        anemic_count += 1
        anemic_cases.append(hb)
    if hb > max_hb:
        max_hb = hb

mean_hb = round(total_hb / len(hb_readings), 2)
print("Mean Hb:", mean_hb, "| Anemic count:", anemic_count)
print("Anemic list:", anemic_cases, "| Highest Hb:", max_hb)

Expected Output:

Mean Hb: 10.96 | Anemic count: 3
Anemic list: [10.4, 9.6, 10.9] | Highest Hb: 12.1

5.3.3 continue & break (DHS Missing Codes & Early Outbreak Alert)

Real epidemiology datasets are never pristine. Demographic and Health Surveys (DHS) routinely encode “refused / not measured” as 999 or None. Use continue to skip bad rows immediately, and break to stop an alert scan the instant a threshold is crossed:

# Part A: continue skips DHS missing sentinels (999 or None)
raw_sbp = [122, 999, 148, None, 134, 999]
valid_total = 0
valid_count = 0

for sbp in raw_sbp:
    if sbp is None or sbp == 999:
        continue
    valid_total += sbp
    valid_count += 1

print("Clean SBP mean:", round(valid_total / valid_count, 1))

# Part B: break halts scan on FIRST outbreak threshold breach (>= 50)
daily_cases = [14, 28, 53, 61, 40]
first_alert_day = None

for day_num, cases in enumerate(daily_cases, start=1):
    if cases >= 50:
        first_alert_day = day_num
        break

print("First outbreak alert on Day:", first_alert_day)

Expected Output:

Clean SBP mean: 134.7
First outbreak alert on Day: 3

Loop Execution Trace Table — Part A (continue Skipping Missing Sentinels):

Iter sbp Skipped (continue)? valid_total valid_count
Init — — 0 0

TipResearcher’s Note — Check is None Before Arithmetic

Notice we wrote if sbp is None or sbp == 999:. Checking is None first is good defensive habit: because of Python’s short-circuit or, if sbp is None, Python skips immediately without ever attempting numeric comparisons like None < 11.0 (which would crash with TypeError)!

5.3.4 enumerate() for Peak Dengue Week Identification

Whenever you need both the position (e.g., Week 1, Week 2, …) and the value, reach for enumerate(sequence, start=1). Passing start=1 aligns Python’s 0-based indexing with human epidemiological week numbers:

# Weekly dengue cases across 6 monsoon weeks
weekly_cases = [32, 48, 79, 115, 94, 61]
peak_week = 1
peak_cases = weekly_cases[0]

for week, cases in enumerate(weekly_cases, start=1):
    if cases > peak_cases:
        peak_cases = cases
        peak_week = week

print(f"Peak dengue week: Week {peak_week} ({peak_cases} cases)")

Expected Output:

Peak dengue week: Week 4 (115 cases)

5.3.5 while Loops: Epidemic Doubling & Hospital Bed Capacity

When you want to simulate forward in time until a clinical threshold is breached—without knowing how many steps it will take—use a while loop:

# Simulate cases doubling every 3 days until exceeding 200 beds
active_cases = 25
bed_capacity = 200
days = 0

while active_cases <= bed_capacity:
    active_cases *= 2
    days += 3

print(f"Capacity exceeded on Day {days} with {active_cases} cases")

Expected Output:

Capacity exceeded on Day 12 with 400 cases

Loop Execution Trace Table (while active_cases <= 200):

Iter Check active_cases <= 200 active_cases After days After
Start 25 <= 200 (True) 25 0
1 50 <= 200 (True) 50 3
2 100 <= 200 (True) 100 6
3 200 <= 200 (True) 200 9
4 400 <= 200 (False \(\rightarrow\) EXIT) 400 12
WarningCommon Trap — Infinite Loops!

If you forget to update the state variable inside a while loop (for instance, forgetting active_cases *= 2), the condition 25 <= 200 stays True forever! In Google Colab, click the Stop (■) button on the cell—and always verify on paper that every while body moves strictly closer to terminating.

5.3.6 Nested Loops: Multi-Ward Surveillance Summary

Real health data is hierarchical: clinics inside districts, days inside wards, visits inside patients. A nested loop places one loop inside another. Watch carefully where ward_total = 0 is reset:

# Each inner list holds 3 daily dengue admissions for one ward
ward_admissions = [
    [6, 9, 11],    # Ward 1 -> sum 26
    [14, 18, 12],  # Ward 2 -> sum 44
]
grand_total = 0

for ward_num, daily_counts in enumerate(ward_admissions, start=1):
    ward_total = 0
    for count in daily_counts:
        ward_total += count
    grand_total += ward_total
    print(f"Ward {ward_num} 3-day total: {ward_total}")

print("Hospital grand total:", grand_total)

Expected Output:

Ward 1 3-day total: 26
Ward 2 3-day total: 44
Hospital grand total: 70

Notice the two accumulator scopes: grand_total = 0 is initialized outside both loops (accumulates the entire hospital), while ward_total = 0 is reset inside the outer loop so Ward 2 does not inherit Ward 1’s 26 admissions!

5.3.7 Break It On Purpose! (Loop Error Anatomy)

ImportantBreak It On Purpose #1 — TypeError: ‘int’ object is not iterable 
for day in 5:
    print("Day:", day)

Python’s Traceback:

TypeError: 'int' object is not iterable

Diagnosis: A single integer (5) is a scalar object, not a sequence of items. Python cannot loop over a single number directly.
Fix: Wrap the count in range(5) (or range(1, 6) for 1-based days): for day in range(1, 6):.

ImportantBreak It On Purpose #2 — NameError on Uninitialized Accumulator 
for cases in [12, 18, 25]:
    uninitialized_total += cases

Python’s Traceback:

NameError: name 'uninitialized_total' is not defined

Diagnosis: uninitialized_total += cases means uninitialized_total = uninitialized_total + cases. On the very first iteration, Python looks up uninitialized_total on the right-hand side and discovers it does not exist yet!
Fix: Initialize uninitialized_total = 0 on the line above the for header.

ImportantBreak It On Purpose #3 — ZeroDivisionError When All Readings Are Missing 
all_missing_hb = [999, 999, 999]
hb_sum = 0.0
valid_n = 0
for val in all_missing_hb:
    if val == 999:
        continue
    hb_sum += val
    valid_n += 1
mean_missing = hb_sum / valid_n

Python’s Traceback:

ZeroDivisionError: float division by zero

Diagnosis: Every reading hit continue, leaving valid_n == 0. Dividing 0.0 / 0 crashes your entire pipeline on the first empty clinic subgroup!
Fix: Always guard the division: mean_missing = round(hb_sum / valid_n, 2) if valid_n > 0 else None.

5.4 Stage 4 — The Researcher’s Problem-Structuring Blueprint

Scenario: A rural maternal health camp collects 7 hemoglobin readings (in g/dL), but two assays failed and were coded as 999 and None: raw_hb = [10.2, 999, 11.6, None, 9.4, 12.3, 10.8]. In a single clean pass, skip missing codes, compute valid_count, mean_hb (rounded to 2 decimals, safely returning None if no valid readings exist), anemic_count (\(< 11.0\text{ g/dL}\)), and min_hb (the lowest valid hemoglobin reading to flag the most severe case).

5.4.1 Blueprint (Completed on Paper Before Coding)

  1. Inputs & Units: List raw_hb containing floats (g/dL), DHS missing code 999, and Python None.
  2. Edge Cases & Traps:
    • Initializing min_hb = raw_hb[0] is dangerous if the first record happens to be 999 or None! Initialize min_hb = None and update whenever min_hb is None or hb < min_hb.
    • Dividing by len(raw_hb) (7) instead of valid_count (5) biases the mean downward.
    • Guard valid_count > 0 before dividing to prevent ZeroDivisionError.
  3. Step-by-Step Algorithm:
    1. Initialize valid_sum = 0.0, valid_count = 0, anemic_count = 0, min_hb = None.
    2. Loop for hb in raw_hb:; if hb is None or hb == 999:, continue.
    3. Update valid_sum += hb, valid_count += 1, check hb < 11.0, and update min_hb.
    4. After the loop, compute mean_hb = round(valid_sum / valid_count, 2) if valid_count > 0 else None.
  4. Verification Plan (Hand Check):
    • Valid readings: \(10.2, 11.6, 9.4, 12.3, 10.8\) (valid_count = 5).
    • Sum: \(10.2 + 11.6 + 9.4 + 12.3 + 10.8 = 54.3\); Mean: \(54.3 / 5 = 10.86\).
    • Anemic (\(< 11.0\)): \(10.2, 9.4, 10.8 \Rightarrow 3\); Minimum: \(9.4\).

5.4.2 Clean Python Implementation (Verbatim in 01_walkthrough.ipynb)

# Step 1: Raw maternal hemoglobin readings with DHS missing codes
raw_hb = [10.2, 999, 11.6, None, 9.4, 12.3, 10.8]

# Step 2: Initialize accumulators, counters, and safe running min
valid_sum = 0.0
valid_count = 0
anemic_count = 0
min_hb = None

# Step 3: Single-pass cleaning + summary loop
for hb in raw_hb:
    if hb is None or hb == 999:
        continue
    valid_sum += hb
    valid_count += 1
    if hb < 11.0:
        anemic_count += 1
    if min_hb is None or hb < min_hb:
        min_hb = hb

# Step 4: Guard against ZeroDivisionError before computing mean
if valid_count > 0:
    mean_hb = round(valid_sum / valid_count, 2)
else:
    mean_hb = None

print(f"Valid: {valid_count} | Mean Hb: {mean_hb} g/dL")
print(f"Anemic: {anemic_count} | Most severe (Min Hb): {min_hb} g/dL")

Output:

Valid: 5 | Mean Hb: 10.86 g/dL
Anemic: 3 | Most severe (Min Hb): 9.4 g/dL

5.8 Stage 8 — Complete Annotated Solutions & Debugging Post-Mortem

5.8.1 A. Concept & Execution Trace Test Key

  1. [2, 4, 6, 8]. range(start, stop, step) is half-open \([2, 10)\), so it stops strictly before 10.
  2. 0 \(\rightarrow\) 8 (\(+4 \times 2\)) \(\rightarrow\) 22 (\(+7 \times 2\)) \(\rightarrow\) 28 (\(+3 \times 2\)).
  3. Prints 10 and 20 only (999 is skipped by continue; -1 triggers break, so 30 is never reached).
  4. total ends at 30 (the last item only), because total = 0 wipes out the accumulated sum at the start of each iteration.
  5. (2, "B") (iteration 1 yields (1, "A"), iteration 2 yields (2, "B")).
  6. With < 200: 50 \(\rightarrow\) 100 \(\rightarrow\) 200 (stops at 200). With <= 200: 200 <= 200 is still True, so it doubles once more to 400.
  7. 10 is a single int, not an iterable sequence. Fix: for i in range(10):.
  8. If every reading is 999, valid_count stays 0, so hb_sum / 0 raises ZeroDivisionError. Guard with if valid_count > 0: ... else: None.
  9. \(4 \times 7 = 28\) total executions.
  10. Because every valid hemoglobin reading (\(> 0\)) is larger than 0, hb < min_hb is never True and min_hb stays stuck at 0! Initialize min_hb = None (and check if min_hb is None or hb < min_hb:) or min_hb = valid_list[0].

5.8.4 D. Debugging Post-Mortem: Top 3 Chapter 5 Failure Modes

  1. Dividing by len(raw_list) Instead of valid_count: After skipping missing 999 and None records with continue, dividing hb_sum by len(raw_hb_readings) (10) instead of valid_count (6) silently fabricates a catastrophic mean hemoglobin of 6.50 g/dL instead of 10.83 g/dL—zero error message, completely corrupted research!
  2. Overwriting First-Occurrence Alerts: In Exam Task 5.2, setting first_alert_week = week unconditionally inside if cases >= 100: overwrites Week 4 with Week 5, Week 6, and finally Week 7. Guarding with if first_alert_week is None: latches onto the earliest breach while letting the loop complete the remaining totals.
  3. Statement-Order Drift Inside while Loops: In Exam Task 5.3, moving daily_admissions += 5 above total_admitted += daily_admissions counts Day 2’s admissions (25) on Day 1—inflating total_admitted from 300 to 340. Always sketch a 2-row Loop Execution Trace Table whenever a while loop updates coupled state variables!
